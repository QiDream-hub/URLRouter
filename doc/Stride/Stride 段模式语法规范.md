# Stride 段模式语法规范

> **实现位置（2026-09-11）**：语法与编译器已从 Stride 迁入 URLRouter 本仓库，
> 实现见 `include/pattern.h`、`src/pattern.c`（词法）与 `src/pattern_compile.c`（编译）。
> 编译产物不再是自己定义的特征/提取操作数组，而是 Stride 的步进序列
> （`stride_seq_t`，见 `include/stride/sequence.h`）。本文档描述的模式语法与
> 编译语义仍然有效，类型与函数名请以当前头文件为准。

**文档版本**：2.0
**更新日期**：2026-09-12
**适用模块**：`stride/compiler.h`（词法分析与序列编译）、`stride/matcher.h`（匹配）、`stride/extractor.h`（提取）

---

> **输入模型**：Stride **只编译单个段（segment，不透明二进制）**的模式，不感知其来源、结构或编码。
> 按 `/`（或调用方约定的任何分隔符）把完整输入切分为段序列由调用方完成，`stride_compile()` 接收的是
> 每一段各自的子模式（例如 `$'user'`、`${}`）。文中含 `/` 的复合书写形式里，`/` 表示**调用方的切分边界**。
>
> **单位**：步长的单位是**比特**——「一步跨越多少比特」。位置与偏移以**步**计，
> 字面量长度、段长、参数长度以**比特**计（`1 字节 = 8 比特`）。

---

## 一、概述

Stride 采用基于**步进偏移**的流式段内解析模型。每个输入单元（段）视为一个不透明**二进制**，
通过操作符序列在该二进制上进行比特串比对、查找与数据捕获。

### 段模型

```
段   = 不透明二进制（比特长度由调用方给出）
步长 = 每步跨越的比特数（由 API 指定）
模式 = 操作符序列（针对单个段编译）
```

设段比特长度 `Lb`、步长 `s`，则段内共有 `N = Lb / s` **步**：

```
比特偏移 = 步序号 × 步长
HEAD（段首）= 第 0 步          END（段尾）= 第 N 步
```

**对齐约束**：`Lb` 必须能被 `s` 整除，否则执行失败（`STRIDE_E_ALIGN`）。

**常见步长**：

| 数据 | 步长（比特/步） |
|------|----------------|
| 位域 / 位标志 | 1 |
| 半字节 / BCD | 4 |
| 字节流（ASCII、UTF-8、Latin-1、任意二进制） | 8 |
| UTF-16 码元 | 16 |
| UTF-32 码元 / 4 字节定长记录 | 32 |
| 8 字节定长记录 | 64 |

> 步长可以是任意正整数，只要长度能被它整除。例如 `$'abc'` = 24 比特，对步长
> 1/2/3/4/6/8/12/24 都合法。**调用方用步长表达“这一段数据的最小单位是多少比特”**。

调用方如何把更大的输入切分成段，不属于本规范的范围。下面给出一个切分视角的示例：调用方按 `/` 切分输入，逐段交给 Stride 编译与执行。

### 示例

```
调用方输入: /user/profile?format=json&lang=zh

调用方按 '/' 切分结果（步长 8 = 1 字节/步）:
  段 0: "user"                            32 比特
  段 1: "profile?format=json&lang=zh"     216 比特

调用方输入: /api/v2.0/users/alice
调用方按 '/' 切分结果（步长 8）:
  段 0: "api"        24 比特
  段 1: "v2.0"       32 比特
  段 2: "users"      40 比特
  段 3: "alice"      40 比特
```

> 若同一输入是 UTF-16 编码，调用方把步长设为 16，语法完全不变——只是 `${n}`、`$[>n]`
> 等操作数表示的是 16 比特一步。

## 二、操作符分类

段模式由以下操作符序列组成，操作符按书写顺序执行。

| 类别 | 操作符 | 说明 |
|------|--------|------|
| 比对操作 | `$'比特串'` | 在当前步精确比对一段二进制 |
| 捕获操作 | `${步数}` | 捕获指定步数 |
| 捕获操作 | `${'比特串'}` | 捕获到指定比特串前（不包含该比特串） |
| 捕获操作 | `${}` | 捕获到段尾 |
| 移动操作 | `$[步位置]` | 绝对定位 |
| 移动操作 | `$[>步数]` | 向段尾方向移动 |
| 移动操作 | `$[<步数]` | 向段首方向移动 |
| 移动操作 | `$[>'比特串']` | 向段尾方向查找比特串 |
| 移动操作 | `$[<'比特串']` | 向段首方向查找比特串 |

**说明**：上表是语法层面的 **9 种操作符书写形式**。词法分析阶段，`$[步位置]` 会依据位置表达式被区分为
`STRIDE_OP_JUMP_ABS`（非负整数）与 `STRIDE_OP_JUMP_END`（`END` / `END − n`）两种操作码，
因此操作符枚举共 10 个常量。

## 三、比对操作

### 3.1 精确比对 - `$'比特串'`

在当前步比对固定二进制串，匹配成功则游标向后移动该串的步数（`bit_len / 步长`）。

| 项目 | 说明 |
|------|------|
| 语法 | `$'比特串'` |
| 游标变化 | 向段尾方向移动 `bit_len / 步长` 步 |
| 产生捕获 | 否 |
| 失败条件 | 比特串不匹配或剩余步数不足 |

**示例（步长 8 = 1 字节/步）：**
```
模式：$'user'
段："user"（32 比特）
结果：比对成功，游标移动到第 4 步

模式：$'用户：'
段："用户：alice"（UTF-8，"用户：" = 72 比特）
结果：比对 72 比特成功，游标移动到第 9 步
```

二进制串是**任意内容**：可以写 UTF-8 中文、UTF-16 码元序列，或用 `\xNN` 转义任意数据
（见第八节）。引擎不解释其编码。

### 3.2 连续字面量的使用建议

两个 `$'比特串'` 可以直接相邻书写，但**不推荐**：

```
// 可以工作，但不推荐
/$'user'$'profile'

// 推荐：合并为一条
/$'userprofile'
```

**原因**：连续字面量在语义上等价于合并后的单条，但会产生冗余元组，轻微影响匹配性能。

## 四、捕获操作

### 4.1 定步捕获 - `${步数}`

从当前步捕获指定步数。

| 项目 | 说明 |
|------|------|
| 语法 | `${步数}` |
| 游标变化 | 向段尾方向移动指定步数 |
| 产生捕获 | 是（参数长度为 `步数 × 步长` 比特） |
| 失败条件 | 剩余步数不足 |

**示例（步长 8）：**
```
模式：${4}
段："2024-03-15"
结果：捕获"2024"（32 比特），游标移动到第 4 步

模式：${3}
段："abc123"
结果：捕获"abc"（24 比特），游标移动到第 3 步
```

**示例（步长 16 = UTF-16 码元）：**
```
模式：${1}
段："中A"（UTF-16LE：AD 4E 41 00，共 32 比特 = 2 步）
结果：捕获第 0 步 = "中"（16 比特），游标移动到第 1 步
```

### 4.2 捕获到定界串 - `${'比特串'}`

从当前步向段尾方向捕获，直到遇到指定比特串（不包含该比特串）。

| 项目 | 说明 |
|------|------|
| 语法 | `${'比特串'}` |
| 游标变化 | 游标移动到定界串的起始步 |
| 产生捕获 | 是 |
| 失败条件 | 无（未找到时捕获到段尾） |

查找在**步对齐**位置进行；未找到时捕获到段尾且不消耗任何内容。

**示例（步长 8）：**
```
模式：${'='}
段："name=alice"
结果：捕获"name"，游标移动到'='所在的第 4 步

模式：${'：'}
段："用户：alice"（UTF-8）
结果：捕获空串（游标已在第 6 步即'：'处），游标保持在'：'起始步
```

### 4.3 捕获到段尾 - `${}`

从当前步捕获到段末尾的所有数据。

| 项目 | 说明 |
|------|------|
| 语法 | `${}` |
| 游标变化 | 游标移动到段尾（第 `N` 步） |
| 产生捕获 | 是 |
| 失败条件 | 永不失败（可能捕获空串） |

```
模式：${}
段："alice"
结果：捕获"alice"（40 比特），游标移动到段尾
```

## 五、移动操作

移动操作用于调整游标位置，不产生捕获。所有数值单位均为**步**。

### 5.1 绝对定位 - `$[步位置]`

| 项目 | 说明 |
|------|------|
| 语法 | `$[步位置]` |
| 位置表达式 | 非负整数 或 `END`（段尾）或 `END − n`（从段尾向段首方向偏移 n 步） |
| 游标变化 | 游标 = 位置表达式的计算结果（单位：步） |
| 产生捕获 | 否 |
| 失败条件 | 计算结果超出段范围（小于 0 或大于 `N`） |

**位置表达式说明：**
- `END` 表示总步数 `N = Lb / 步长`（即段尾）
- `END − n` 表示从段尾向段首方向偏移 n **步**
- 计算结果必须满足 `0 ≤ 位置 ≤ N`

**示例（步长 8）：**
```
模式：$[0]
段："user"        → 游标移动到第 0 步（段首）

模式：$[5]
段："profile?format=json" → 游标移动到第 5 步

模式：$[END]
段："alice"       → 游标移动到第 5 步（段尾）

模式：$[END-4]
段："document.pdf" → 游标移动到第 8 步（总步数 12 减 4）
```

**示例（步长 16）：**
```
模式：$[END-1]
段："中A"（32 比特 = 2 步）
结果：游标移动到第 1 步（比特偏移 16，即字符'A'处）
```

### 5.2 向段尾移动 - `$[>步数]`

| 项目 | 说明 |
|------|------|
| 语法 | `$[>步数]` |
| 游标变化 | 游标 += 步数 |
| 产生捕获 | 否 |
| 失败条件 | 移动后位置超过 `N` |

```
模式：$[>3]        段："abc123"          当前游标 0 → 第 3 步
模式：$[>1]        段："name=alice&age=25" 当前游标 10（'&'）→ 第 11 步
```

### 5.3 向段首移动 - `$[<步数]`

| 项目 | 说明 |
|------|------|
| 语法 | `$[<步数]` |
| 游标变化 | 游标 −= 步数 |
| 产生捕获 | 否 |
| 失败条件 | 移动后位置小于 0 |

```
模式：$[<4]        段："document.pdf"    当前游标 12（段尾）→ 第 8 步（'.'）
模式：$[<0]        段："v2.5.1"          当前游标 6 → 第 0 步（段首）
```

### 5.4 向段尾查找比特串 - `$[>'比特串']`

| 项目 | 说明 |
|------|------|
| 语法 | `$[>'比特串']` |
| 游标变化 | 游标移动到**最靠前**的匹配起始步 |
| 产生捕获 | 否 |
| 失败条件 | 未找到指定比特串 |

查找只在步对齐位置进行，因此不会匹配到某个步的内部。

```
模式：$[>'=']      段："name=alice"       当前游标 0 → 第 4 步（'='）
模式：$[>'&']      段："q=router&page=2"  当前游标 0 → 第 10 步（'&'）
模式：$[>'：']     段："用户：alice"（UTF-8）当前游标 0 → 第 6 步（'：'起始）
```

### 5.5 向段首查找比特串 - `$[<'比特串']`

| 项目 | 说明 |
|------|------|
| 语法 | `$[<'比特串']` |
| 游标变化 | 游标移动到**最靠后**的匹配起始步 |
| 产生捕获 | 否 |
| 失败条件 | 未找到指定比特串 |

查找起点为“当前游标的前一步”；当游标位于段首（第 0 步）时，从段尾（第 `N−1` 步）开始。

```
模式：$[<'=']      段："name=alice"       当前游标 9（段尾）→ 第 4 步（'='）
模式：$[<'&']      段："q=router&page=2"  当前游标 15（段尾）→ 第 10 步（'&'）
模式：$[<'ab']     段："ab--ab--ab"       当前游标 10（段尾）→ 第 6 步（最后一次 "ab"）
```

## 七、语法规则

### 7.1 执行模型

1. 每个段维护一个解析游标，单位为**步**，初始值为 0，始终满足 `0 ≤ 游标 ≤ N`
2. 操作符按书写顺序依次执行
3. 每个操作完成后游标自动更新
4. 所有操作都必须进行边界检查
5. 任何操作失败则整个段匹配失败

### 7.2 边界检查

| 操作符 | 边界条件 |
|--------|----------|
| `$'比特串'` | 当前步 + `bit_len / 步长` ≤ `N` |
| `${步数}` | 当前步 + 步数 ≤ `N` |
| `${'比特串'}` | 无硬性限制（未找到时捕获到段尾） |
| `${}` | 无限制 |
| `$[步位置]` | 位置表达式计算结果在 `[0, N]` 范围内 |
| `$[>步数]` | 当前步 + 步数 ≤ `N` |
| `$[<步数]` | 当前步 − 步数 ≥ 0 |
| `$[>'比特串']` | 无硬性限制（未找到时匹配失败） |
| `$[<'比特串']` | 无硬性限制（未找到时匹配失败） |

### 7.3 对齐约束

设步长 `s`、段比特长度 `Lb`：

| 约束 | 违反时 |
|------|--------|
| `Lb % s == 0` | 执行失败，`STRIDE_E_ALIGN` |
| 每个字面量 `bit_len % s == 0` | 编译期已知步长时编译失败，否则执行失败 |

对齐约束保证游标始终落在步边界上：既不会读到某个“步”的中间，也不会让后续
`${n}`、`$[>n]` 等操作错位。

**示例**：
```
步长 8：  $'abc'（24 比特）→ 24 % 8 == 0  → 合法
步长 16： $'abc'（24 比特）→ 24 % 16 != 0 → 失败（$'abc' 不是 2 字节的整数倍）
步长 4：  $'abc'（24 比特）→ 24 % 4 == 0  → 合法
```

> 因此 `$'abc'` 与「步长 2」并不冲突：24 是 2 的整数倍。真正冲突的是步长与比特长度不整除的情形。

### 7.4 段匹配结束条件

段匹配成功需同时满足：

1. **操作耗尽**：所有操作符均已执行完毕
2. **游标对齐**：当前游标位置等于总步数 `N`（即段尾）

若操作耗尽但游标未到达段尾，匹配失败。此规则确保模式完整消耗整个段，避免部分匹配导致的歧义。

**示例（步长 8）：**
```
模式：${2}
段："ab"    → 游标移动到 2，等于 N → 匹配成功
段："abc"   → 游标移动到 2，小于 N → 匹配失败

模式：${2}$'c'
段："abc"   → 操作耗尽时游标位于 3，等于 N → 匹配成功
```

**示例（步长 32 = 4 字节/步）：**
```
模式：${1}
段："abc"    → 24 比特，24 % 32 != 0 → 对齐失败（STRIDE_E_ALIGN）
段："abcd"   → 32 比特 = 1 步；游标 1 == N → 匹配成功
```

### 7.5 参数捕获

1. 捕获按操作符执行顺序依次存储
2. 每个捕获操作产生一个参数
3. 多个段产生的参数由调用方按段顺序连接（Stride 只负责单段内的捕获）
4. 参数以（起始指针，**比特长度**）形式返回，直接指向原始段数据，不进行复制；
   在 Stride API 中表示为 `stride_param_t { const void *ptr; size_t bit_len; }`（零拷贝）
5. 空参数通过长度为零表示
6. 参数长度为 `步数 × 步长` 比特；调用方按原始二进制解释其内容
7. 参数的**起始位置必须字节对齐**（比特偏移是 8 的整数倍）。例如步长 4 时，从第 1 步
   （比特 4）开始的捕获无法用 `(ptr, bit_len)` 表达，执行会失败；从第 0 步开始的捕获正常。
   步长为 8 的整数倍时该限制自动满足

## 八、比特串与转义

引号内的内容是**任意二进制串**。为避免与语法字符冲突，支持以下转义：

| 转义 | 含义 |
|------|------|
| `\\` | 一个反斜杠字节（8 比特） |
| `\'` | 一个单引号字节（8 比特） |
| `\xNN` | 一个任意字节（8 比特） |

其余字符按源码原样取字节；字面量的 `bit_len = 8 × 字节数`。因此：

```
$'中文'                 // 源码为 UTF-8 时 = 48 比特（每个汉字 24 比特）
$'A\x00'                // 'A' 加一个 0x00 字节 = 16 比特（如 UTF-16LE 的字符 'A'）
$'\xEF\xBC\x9A'         // 全角冒号 "：" 的 UTF-8 字节 = 24 比特
$'it\'s'                // 含单引号的字面量
```

> **模式本身是单字节 ASCII 语法流**：`$`、`{`、`}`、`[`、`]`、`'` 等语法字符恒为单字节；
> 步长只作用于**段**与**字面量载荷**，不改变语法的书写方式。
>
> 需要匹配含 `'\0'` 的二进制模式时，使用长度化接口 `stride_lex(pattern, pattern_len, ...)` /
> `stride_compile_ex(pattern, pattern_len, stride)`，在 `pattern_len` 内可包含真实的 `0x00`。

## 九、语法限制

1. 操作符必须按规范书写
2. 段模式不能为空
3. **分隔符由调用方处理**：如何按 `/` 等把输入切分为段由调用方负责。`/` 本身**不是非法字符**，
   它出现在引号内即为普通字面量数据（`$'////'` 合法）；只有**游离在引号外、不以 `$` 起始**的字节
   （如 `$'a'/${}` 中的 `/`）才是语法错误
4. 偏移值必须是非负整数（单位：步）
5. 捕获步数必须是正整数
6. 定界串比特长度必须 ≥ 1，且为步长的整数倍
7. 位置表达式中的 `END` 后只能跟 `− n` 形式的偏移，n 为非负整数（单位：步）
8. **定步捕获和捕获到定界串的区分**：
   - `${数字}` - 定步捕获，如 `${4}` 捕获 4 **步**
   - `${'比特串'}` - 捕获到定界串，如 `${'='}` 捕获到'='之前
9. **移动操作和捕获操作的区分**：
   - `$[>'比特串']` - 查找移动，不捕获
   - `${'比特串'}` - 捕获到定界串，产生参数

## 十、完整模式示例

以下示例使用含 `/` 的复合书写形式，其中 `/` 是**调用方的切分边界**；每一段分别由 Stride 编译
（例如 `stride_compile("$'user'")`）与执行，段间不做任何跨段操作。除特别注明外，步长为 **8（1 字节/步）**。

### 10.1 基础示例

```
模式：/$'user'/${}
输入:  /user/alice

段 0: $'user' → 比对"user"
段 1: ${} → 捕获"alice"

捕获结果：["alice"]
```

### 10.2 查询参数

```
模式：/$'search'$'?'$[>'=']$'='${}
输入:  /search?q=router

段 0: $'search' → 比对"search"
段 1:
  $'?'        → 比对"?"
  $[>'=']     → 查找'='，游标移动到'='处
  $'='        → 比对"="
  ${}         → 捕获"router"

捕获结果：["router"]
```

### 10.3 多参数查询

```
模式：/$'search'$'?'${'='}$'='${'&'}$[>1]${'='}$'='${}
输入:  /search?q=router&page=2

段 0: $'search' → 比对"search"
段 1:
  $'?'        → 比对"?"
  ${'='}      → 捕获"q"
  $'='        → 比对"="
  ${'&'}      → 捕获"router"
  $[>1]       → 跳过'&'
  ${'='}      → 捕获"page"
  $'='        → 比对"="
  ${}         → 捕获"2"

捕获结果：["q", "router", "page", "2"]
```

### 10.4 版本号解析

```
模式：/$'api'/$'v'${'.'}$'.'${}
输入:  /api/v2.0

段 0: $'api' → 比对"api"
段 1:
  $'v'        → 比对"v"
  ${'.'}      → 捕获"2"
  $'.'        → 比对"."
  ${}         → 捕获"0"

捕获结果：["2", "0"]
```

### 10.5 文件名和扩展名

```
模式：/$'files'/${'.'}$'.'${}
输入:  /files/document.pdf

段 0: $'files' → 比对"files"
段 1:
  ${'.'}      → 捕获"document"
  $'.'        → 比对"."
  ${}         → 捕获"pdf"

捕获结果：["document", "pdf"]
```

### 10.6 定步段限制

```
模式：/${2}/$'key'
输入:  /ab/key

段 0: ${2} → 捕获"ab"（16 比特），游标移动到 2 = N → 匹配成功
段 1: $'key' → 比对"key"

捕获结果：["ab"]
```

### 10.7 回溯捕获（先完整后拆分）

```
模式：/$'file'/${}$[0]${'.'}$'.'${}
输入:  /file/document.pdf

段 0: $'file' → 比对"file"
段 1:
  ${}         → 捕获"document.pdf"
  $[0]        → 移动到第 0 步
  ${'.'}      → 捕获"document"
  $'.'        → 比对"."
  ${}         → 捕获"pdf"

捕获结果：["document.pdf", "document", "pdf"]
```

### 10.8 日期解析

```
模式：/$'logs'/${4}$'-'${2}$'-'${2}
输入:  /logs/2024-03-15

段 0: $'logs' → 比对"logs"
段 1:
  ${4}        → 捕获"2024"
  $'-'        → 比对"-"
  ${2}        → 捕获"03"
  $'-'        → 比对"-"
  ${2}        → 捕获"15"

捕获结果：["2024", "03", "15"]
```

### 10.9 使用查找移动跳过前缀

```
模式：/$'log'$[>'\_']$[>1]${8}
输入:  /log/2024-03-15_ERROR_message

段 0: $'log' → 比对"log"
段 1:
  $[>'\_']    → 查找'_'，游标移动到'_'处
  $[>1]       → 跳过'_'（1 步 = 8 比特）
  ${8}        → 捕获 8 步 = 64 比特

捕获结果：["ERROR_me"]
```

### 10.10 从段尾向前查找

```
模式：/$[<'=']${}
输入:  /name=alice

段 0:
  $[<'=']     → 从段尾向前查找'='，游标移动到'='处
  ${}         → 捕获"=alice"（从'='到段尾）

捕获结果：["=alice"]
```

### 10.11 检查文件扩展名

```
模式：/$[<'\.']$'.pdf'
输入:  /doc.pdf

段 0:
  $[<'\.']    → 从段尾向前查找'.'，游标移动到'.'处
  $'.pdf'     → 比对".pdf"

捕获结果：[]  // 仅验证扩展名，不捕获
```

### 10.12 多比特定界（UTF-8，步长 8）

```
模式：/$'用户'/${'：'}$'：'${}
输入:  /用户/alice

段 0: $'用户' → 比对 48 比特
段 1:
  ${'：'}     → 查找全角冒号（24 比特），捕获空串，游标停在'：'起始处
  $'：'       → 比对 24 比特的'：'，游标跳过它
  ${}         → 捕获"alice"

捕获结果：["", "alice"]
```

更紧凑的写法是把定界串并入前一个比对：

```
模式：/$'用户：'/${}
捕获结果：["alice"]
```

### 10.13 定宽编码（UTF-16LE，步长 16）

```
模式：/$'U\x00'/${1}$'A\x00'
输入（UTF-16LE 段）: /U/中A
      段 0 比特: 16           （1 步）
      段 1 比特: 32           （2 步：AD 4E | 41 00）

段 0: $'U\x00'   → 比对 16 比特（UTF-16LE 的 'U'）
段 1:
  ${1}           → 捕获第 0 步 = 16 比特（"中"）
  $'A\x00'       → 比对第 1 步 = 16 比特（"A"）

捕获结果：["中"]
```

> 定宽编码下字面量比特长度必须是步长整数倍：步长 16 时写 `$'U\x00'`（16 比特）而非
> `$'U'`（8 比特，违反对齐约束）。

### 10.14 定长二进制记录（步长 = 记录位宽）

```
模式：/${1}$'OK\x00\x00'${1}
段（每条记录 32 比特 = 4 字节，步长 32）:
  记录 0: 01 02 03 04
  记录 1: 4F 4B 00 00   （"OK" + 填充）
  记录 2: 05 06 07 08

  ${1}            → 捕获记录 0（32 比特）
  $'OK\x00\x00'   → 比对记录 1（32 比特）
  ${1}            → 捕获记录 2（32 比特）

捕获结果：[记录0 的 32 比特, 记录2 的 32 比特]
```

## 十一、设计原则

1. **段独立性**：每段解析完全独立，不跨段操作
2. **内容无关性**：段是二进制，引擎不解释其结构或编码
3. **比特为单位**：步长是「每步比特数」；长度以比特计，位置以步计
4. **比特串比对**：比对与查找的目标是任意长度比特串，多字节内容无需特殊支持
5. **对齐约束**：段长与字面量长度必须是步长的整数倍，保证游标始终落在步边界
6. **确定性**：模式确定，无可选分支，无条件匹配
7. **最小化**：语法层面只保留 9 个正交的基础操作符书写形式（词法分析后对应 10 个操作码常量）
8. **段尾对齐**：每个段匹配完成后游标必须位于段尾
9. **职责分离**：移动操作（`$[]`）只移动不捕获，捕获操作（`${}`）负责捕获
10. **切分无关**：Stride 与分隔符无关，输入切分由调用方负责
