# URLRouter 路由语法规范

**文档版本**：1.0
**更新日期**：2026-09-11
**适用范围**：URLRouter 段模式语法（`router_register()` 传入的路由模式字符串）

> 本文档以当前实现为准：词法分析器 `url_lex()` 与编译器 `url_compile()` 位于
> `include/pattern.h` 及其实现单元中，路由与分隔符规则见 `include/router.h`。
> 若本文档与代码不一致，以代码为准。

## 1. 概述

URLRouter 是一个为 C 语言设计的 URL 路由库。它把 URL 路径按**分隔符**切分为若干**段**，
每一段再用一段**段模式**描述其形状；所有段都匹配成功时路由命中，随后可以按需从原始 URL
中**零拷贝**地提取参数。

### 1.1 URL 模型

```
URL 路径 = 分隔符 段 { 分隔符 段 }
段       = 分隔符之外的任意字节序列
```

- 路径必须以分隔符开头（URL 场景即 `/`）。
- 分隔符本身不属于任何段：切分时它被去掉，段模式只描述单个段的**内容**。
- 段之间只允许出现一个分隔符；连续分隔符会产生**空段**，空段被拒绝。
- 尾随分隔符被忽略：`/user/alice/` 与 `/user/alice` 切分结果相同。
- 除分隔符之外的字节都留在段内。因此查询串也是段的一部分：
  `/search?q=router` 只有 1 个段，即 `"search?q=router"`。

### 1.2 按分隔符切段

以分隔符 `/` 为例：

```
URL: /api/v2.0/users/alice

段 0: "api"      4 字节
段 1: "v2.0"     4 字节
段 2: "users"    5 字节
段 3: "alice"    5 字节
```

共 **4 段**，因此路由模式也必须写成 4 段，例如
`/$'api'/$'v'${'.'}$'.'${}/$'users'/${}`。

再看一个含查询串的例子：

```
URL: /user/profile?format=json&lang=zh

段 0: "user"                             4 字节
段 1: "profile?format=json&lang=zh"     28 字节
```

`?`、`&`、`=` 都不是分隔符，它们只是段内的普通字节。

### 1.3 段模式的作用

段模式负责回答两件事：

1. **这一段长什么样**：用精确比对（`$'文本'`）与定位/查找（`$[...]`）描述段的形状，
   并决定该路由是否命中。
2. **要从这一段里取走什么**：用捕获操作（`${n}`、`${'文本'}`、`${}`）声明参数，
   命中后按需提取。

```c
router_t *r = router_create('/');

/* 两段：第 1 段精确为 "user"，第 2 段整体捕获 */
router_register(r, HTTP_GET, "/$'user'/${}", handler, NULL);

route_node_t *node = router_match(r, HTTP_GET, "/user/alice");
route_param_t params[8];
size_t count = 0;
router_extract(node, "/user/alice", params, 8, &count);  /* count == 1，"alice" */
```

### 1.4 单位：字节

URLRouter 是**字节导向**的：编译与执行统一使用 `URL_PATTERN_STRIDE = 8`，即
**1 步 = 1 字节**。因此本文档中所有「步数 / 位置 / 偏移 / 长度」的单位都是**字节**。

- 段长以字节计；段内游标 `0` 表示段首（HEAD），`段长` 表示段尾（END）。
- 字面量按字节读取：UTF-8 下一个汉字占 3 字节，例如 `$'用户'` 是 6 字节。
- URL 段长、字面量长度天然是 8 的整数倍，对齐约束自动满足（见第 6 节第 6 条）。

### 1.5 匹配成功的判定

一段匹配成功必须**同时**满足两个条件：

1. **操作耗尽**：模式中的所有操作都已执行完毕；
2. **段尾对齐**：执行结束时游标恰好位于段尾。

任何操作失败、或操作耗尽但游标没有停到段尾，该段匹配失败，整个路由不命中。详见第 5 节。

## 2. 完整操作符表（10 个操作码 / 9 类书写形式）

段模式由下表操作符按书写顺序组成。所有操作符都以 `$` 起始。

| 操作符 | 操作码（内部 IR） | 说明 | 指针变化（段内游标，字节） | 产生参数 | 失败条件 |
|--------|------------------|------|---------------------------|----------|----------|
| `$'文本'` | `URL_OP_MATCH` | 在当前游标处精确比对「文本」的字节序列，可多字节、可含转义 | 游标 `+=` 文本字节数 | 否 | 剩余字节不足，或内容不完全相同 |
| `${n}` | `URL_OP_CAPTURE_STEPS` | 从当前游标捕获 `n` 字节 | 游标 `+= n` | 是（长度 `n`） | `n == 0` 为编译期语法错误；`pos + n > 段长` |
| `${'文本'}` | `URL_OP_CAPTURE_UNTIL` | 从当前游标捕获到「文本」之前（**不含**该文本） | 游标 = 该文本首字节 | 是（游标到该文本之间，可为空） | 从当前游标起在段内找不到该文本（匹配阶段失败） |
| `${}` | `URL_OP_CAPTURE_END` | 从当前游标捕获到段尾 | 游标 = 段尾 | 是（游标到段尾，可为空） | 无（永不失败） |
| `$[n]` | `URL_OP_JUMP_ABS` | 绝对定位到段首之后第 `n` 字节（基于 HEAD） | 游标 = `n` | 否 | `n > 段长` |
| `$[END]` / `$[END-n]` | `URL_OP_JUMP_END` | 定位到段尾 / 段尾前 `n` 字节 | 游标 = `段长 − n` | 否 | `n > 段长` |
| `$[>n]` | `URL_OP_JUMP_FWD` | 从当前游标向段尾前进 `n` 字节 | 游标 `+= n` | 否 | `n > 段长 − 游标` |
| `$[<n]` | `URL_OP_JUMP_BACK` | 从当前游标**后退** `n` 字节 | 游标 `−= n` | 否 | `n > 游标`（游标在段首时任何 `n > 0` 都失败） |
| `$[>'文本']` | `URL_OP_FIND_FWD` | 向段尾方向查找「文本」，落点为其首字节 | 游标 = 从当前游标起第一个命中位置（可以就是当前游标） | 否 | 从当前游标到段尾之间找不到 |
| `$[<'文本']` | `URL_OP_FIND_REV` | 向段首方向查找「文本」，落点为其首字节 | 游标 = 向前最近的命中起始位置 | 否 | 找不到 |

### 关于「10 个操作码 / 9 类书写形式」

- 上表共 **10 行**，对应词法分析产出的 **10 个操作码常量**（`URL_OP_MATCH`、
  `URL_OP_CAPTURE_STEPS`、`URL_OP_CAPTURE_UNTIL`、`URL_OP_CAPTURE_END`、
  `URL_OP_JUMP_ABS`、`URL_OP_JUMP_END`、`URL_OP_JUMP_FWD`、`URL_OP_JUMP_BACK`、
  `URL_OP_FIND_FWD`、`URL_OP_FIND_REV`）。
- 若按「方括号里写什么」归类，`$[n]` 与 `$[END]`、`$[END-n]` 同属
  **`$[位置]`（绝对定位）一类书写形式**：位置表达式要么是非负整数，要么是 `END`
  或 `END-n`。这样语法层面共 **9 类书写形式**：
  `$'文本'`、`${n}`、`${'文本'}`、`${}`、`$[位置]`、`$[>n]`、`$[<n]`、`$[>'文本']`、`$[<'文本']`。

因此请以「**10 个操作码 / 9 类书写形式**」理解本语法：书写形式 9 类，词法分析后展开为 10 个操作码。

> 注意：`END` 的形式就是 `$[END]` 或 `$[END-n]`，没有其它写法。既不能写 `$[END+4]`，
> 也不能把 `END` 当成某种「第四种位置参数」而省略方括号语法。

## 3. 转义规则

单引号内的文本**按字节读取**，支持以下转义（仅这些）：

| 转义 | 含义 | 字节数 |
|------|------|--------|
| `\\` | 一个反斜杠字节 `0x5C` | 1 |
| `\'` | 一个单引号字节 `0x27` | 1 |
| `\n` | 换行 `0x0A` | 1 |
| `\t` | 制表符 `0x09` | 1 |
| `\r` | 回车 `0x0D` | 1 |
| `\0` | 空字节 `0x00` | 1 |
| `\xNN` | 任意字节，`NN` 为**恰好两位**十六进制（大小写均可） | 1 |

规则与示例：

1. **反斜杠后必须是上表字符**：`\.`、`\_`、`\a`、`\d` 等都是语法错误。
   想匹配一个点，直接写 `$'.'`；想匹配下划线，直接写 `$'_'`。
   要匹配反斜杠本身才写 `$'\\'`。
2. **`\x` 必须紧跟恰好两位十六进制**：`\x09`、`\xFF` 合法；`\x9`、`\x`、`\xZZ` 非法。
   `\xABC` 表示字节 `0xAB` 后跟字符 `C`。
3. **未转义字符按源码原样取字节**，可多字节直接书写：
   - `$'用户'`：UTF-8 源码下为 6 字节。
   - `$[>'：']`：全角冒号，UTF-8 下为 3 字节。
   - `$'\xEF\xBC\x9A'` 与 `$'：'` 等价（都是全角冒号的 UTF-8 字节）。
4. **文本必须用单引号包裹，且引号必须闭合**：`$'abc`、`${'abc}`、`$[>'abc]` 都是语法错误。
5. 引号内的 `$`、`{`、`}`、`[`、`]`、`/`、`.`、`?`、`&`、`=` 都是普通字节，无需转义；
   引号内只有 `\` 和 `'` 需要通过 `\\`、`\'` 表示。
6. 文本可以为空：`$''` 合法（空比对，等效于无操作）；`${''}`、`$[>'']`、`$[<'']`
   语法上可写，但匹配阶段把空目标视为「未找到」，因此永远不会匹配成功，应避免（见第 8 节）。

示例：

```
模式：$'it\'s'
段：  "it's"（4 字节）
结果：比对成功，游标 0 → 4

模式：$'a\nb'
段：  "a\nb"（3 字节：'a'、换行、'b'）
结果：比对成功，游标 0 → 3
```

## 4. 操作符详解

本节每个操作符都给出语法、游标变化、是否产生参数、失败条件与示例。
示例统一约定：**模式**是单个段的模式；**段**是该段的实际字节内容；**游标**是段内偏移（字节）。

### 4.1 精确比对 `$'文本'`

在当前游标处比对「文本」的全部字节，完全相等才算通过。

| 项目 | 说明 |
|------|------|
| 语法 | `$'文本'`（文本可多字节、可含转义） |
| 游标变化 | `游标 += 文本字节数` |
| 产生参数 | 否 |
| 失败条件 | `游标 + len(文本) > 段长`，或任一字节不相等 |

示例 1（成功）：

```
模式：$'user'
段：  "user"（4 字节）
游标：0 → 4
结果：比对成功；游标 4 = 段长 → 该段匹配成功，无参数
```

示例 2（段尾未对齐导致整段失败）：

```
模式：$'user'
段：  "userx"（5 字节）
游标：0 → 4
结果：比对本身成功，但操作耗尽时游标 4 ≠ 5 → 该段匹配失败
```

示例 3（内容不足/不等）：

```
模式：$'users'
段：  "user"（4 字节）
结果：剩余 4 字节 < 5 字节 → 失败

模式：$'user'
段：  "User"（4 字节）
结果：首字节大小写不同 → 失败（本语法大小写敏感）
```

示例 4（多字节字面量）：

```
模式：$'用户'${}
段：  "用户：alice"（14 字节：用户 6 + ：3 + alice 5）
游标：0 → 6 → 14
结果：比对 6 字节成功，随后 ${} 捕获 "：alice"（7 字节）；参数 ["：alice"]
```

> 建议：相邻的多个字面量（`$'user'$'profile'`）虽然合法，但语义等价于
> `$'userprofile'`，而且会多出一个序列节点。推荐合并成一条书写。

### 4.2 定长捕获 `${n}`

从当前游标捕获固定 `n` 字节。

| 项目 | 说明 |
|------|------|
| 语法 | `${n}`，`n` 为**正整数**（`n ≥ 1`） |
| 游标变化 | `游标 += n` |
| 产生参数 | 是，参数长度为 `n` 字节 |
| 失败条件 | `n == 0` 为编译期语法错误；`游标 + n > 段长` 时匹配失败 |

示例 1（恰好消耗整段）：

```
模式：${4}
段：  "2024"（4 字节）
游标：0 → 4
结果：捕获 "2024"；游标 4 = 段长 → 成功
```

示例 2（段更长 → 段尾未对齐）：

```
模式：${4}
段：  "2024-03-15"（10 字节）
游标：0 → 4
结果：捕获 "2024"，但游标 4 ≠ 10 → 该段匹配失败
```

示例 3（与其他操作组合）：

```
模式：${4}$'-'${2}$'-'${2}
段：  "2024-03-15"（10 字节）
游标：0 → 4 → 5 → 7 → 8 → 10
结果：参数 ["2024", "03", "15"]；游标 10 = 段长 → 成功
```

示例 4（长度不足）：

```
模式：${5}
段：  "2024"（4 字节）
结果：5 > 4 → 失败
```

### 4.3 捕获到定界文本 `${'文本'}`

从当前游标向段尾方向查找「文本」，捕获游标到该文本**之前**的内容（不含该文本），
并把游标移动到该文本的首字节。

| 项目 | 说明 |
|------|------|
| 语法 | `${'文本'}` |
| 游标变化 | 游标 = 命中文本的首字节（未命中时为段尾，见下） |
| 产生参数 | 是；命中位置就在游标处时产生**空参数**（长度 0） |
| 失败条件 | 从当前游标起找不到该文本 → 该段匹配失败 |

> **匹配阶段与提取阶段的差异（重要）**：该操作在匹配阶段被实现为一次「向段尾查找」，
> 找不到定界文本时匹配直接失败；在提取阶段的捕获动作本身对「未找到」是宽容的
> ——会退化为捕获到段尾。由于匹配先行，实际路由中 `${'文本'}` 只有在定界文本
> **确实存在**时才会命中。需要「定界文本可有可无」的效果时，请改用 `${}`、
> `$[>'文本']` 等组合。

示例 1（基本用法）：

```
模式：${'='}$'='${}
段：  "name=alice"（10 字节）
游标：0 → 4 → 5 → 10
解析：${'='} 命中下标 4 的 '='，捕获 "name"；$'=' 比对并跳过 '='；${} 捕获 "alice"
结果：参数 ["name", "alice"]
```

示例 2（定界文本是数字）：

```
模式：${'4'}${}
段：  "abc4def"（7 字节）
游标：0 → 3 → 7
解析：${'4'} 命中下标 3 的 '4'，捕获 "abc"；${} 捕获 "4def"
结果：参数 ["abc", "4def"]
```

示例 3（多字节定界文本）：

```
模式：${'：'}$'：'${}
段：  "用户：alice"（14 字节）
游标：0 → 6 → 9 → 14
解析：${'：'} 在 3 字节的全角冒号处命中，捕获 "用户"（6 字节）
结果：参数 ["用户", "alice"]
```

示例 4（空参数）：

```
模式：$'用户'${'：'}$'：'${}
段：  "用户：alice"（14 字节）
游标：0 → 6 → 6 → 9 → 14
解析：$'用户' 比对 6 字节后，游标正好停在 '：' 起点；${'：'} 原地命中 →
     捕获空串（长度 0），游标不动
结果：参数 ["", "alice"]
```

示例 5（找不到 → 失败）：

```
模式：${'x'}${}
段：  "abc"（3 字节）
结果：段内不存在 'x' → 匹配阶段失败，该路由不命中
```

### 4.4 捕获到段尾 `${}`

从当前游标一直捕获到段尾。

| 项目 | 说明 |
|------|------|
| 语法 | `${}` |
| 游标变化 | 游标 = 段尾 |
| 产生参数 | 是；游标本来就在段尾时产生空参数（长度 0） |
| 失败条件 | 无（永不失败） |

示例 1（整段捕获）：

```
模式：${}
段：  "alice"（5 字节）
游标：0 → 5
结果：参数 ["alice"]；游标 5 = 段长 → 成功
```

示例 2（先比对前缀再捕获）：

```
模式：$'-'${}
段：  "-result"（7 字节）
游标：0 → 1 → 7
结果：参数 ["result"]
```

示例 3（空参数）：

```
模式：$'ab'${}
段：  "ab"（2 字节）
游标：0 → 2 → 2
结果：参数 [""]（长度 0）；游标 2 = 段长 → 成功
```

### 4.5 绝对定位 `$[n]`

把游标直接设为「段首 + `n` 字节」。

| 项目 | 说明 |
|------|------|
| 语法 | `$[n]`，`n` 为非负整数（基于 HEAD，即段首） |
| 游标变化 | 游标 = `n`（与移动前的游标无关） |
| 产生参数 | 否 |
| 失败条件 | `n > 段长` |

示例 1：

```
模式：$[2]${}
段：  "abcdef"（6 字节）
游标：0 → 2 → 6
结果：参数 ["cdef"]
```

示例 2（定位到段尾是合法位置）：

```
模式：$[3]
段：  "abc"（3 字节）
游标：0 → 3
结果：无参数；游标 3 = 段长 → 成功
```

示例 3（越界）：

```
模式：$[5]${}
段：  "abc"（3 字节）
结果：5 > 3 → 失败
```

示例 4（重新定位，实现「先整体后拆分」，详见 9.6）：

```
模式：${}$[0]${'.'}$'.'${}
段：  "document.pdf"（12 字节）
游标：0 → 12 → 0 → 8 → 9 → 12
结果：参数 ["document.pdf", "document", "pdf"]
```

### 4.6 定位到段尾 `$[END]` / `$[END-n]`

`$[END]` 把游标设为段尾；`$[END-n]` 把游标设为「段尾前 `n` 字节」。

| 项目 | 说明 |
|------|------|
| 语法 | `$[END]` 或 `$[END-n]`（`n` 为非负整数、单位字节；`END` 必须全大写） |
| 游标变化 | `$[END]`：游标 = 段长；`$[END-n]`：游标 = `段长 − n` |
| 产生参数 | 否 |
| 失败条件 | `n > 段长` |

示例 1（`$[END]` 本身就是一种「任意段」匹配）：

```
模式：$[END]
段：  "alice"（5 字节）
游标：0 → 5
结果：无参数；游标 5 = 段长 → 成功
（该模式不比对任何内容，可匹配任意非空段，但不产生参数）
```

示例 2（从段尾向前取扩展名）：

```
模式：$[END-4]${}
段：  "document.pdf"（12 字节）
游标：0 → 8 → 12
结果：参数 [".pdf"]（从下标 8 到段尾）
```

示例 3（跳到固定偏移后定长捕获）：

```
模式：$[END-4]${4}
段：  "abcdefgh"（8 字节）
游标：0 → 4 → 8
结果：参数 ["efgh"]
```

示例 4（越界）：

```
模式：$[END-9]
段：  "abc"（3 字节）
结果：9 > 3 → 失败
```

> `$[END-0]` 与 `$[END]` 等价。`END` 大小写敏感，`$[end]` 是语法错误。

### 4.7 前进 `$[>n]`

从当前游标向段尾方向移动 `n` 字节，不做比对、不产生参数。

| 项目 | 说明 |
|------|------|
| 语法 | `$[>n]`，`n` 为非负整数 |
| 游标变化 | `游标 += n` |
| 产生参数 | 否 |
| 失败条件 | `游标 + n > 段长` |

示例 1：

```
模式：$[>3]${}
段：  "abc123"（6 字节）
游标：0 → 3 → 6
结果：参数 ["123"]
```

示例 2（跳过固定前缀）：

```
模式：$[>11]${}
段：  "2024-03-15_message"（18 字节）
游标：0 → 11 → 18
结果：参数 ["message"]
```

示例 3（`n = 0` 合法，原地不动）：

```
模式：$[>0]${}
段：  "abc"（3 字节）
游标：0 → 0 → 3
结果：参数 ["abc"]
```

示例 4（越界）：

```
模式：$[>4]${}
段：  "abc"（3 字节）
结果：4 > 3 → 失败
```

### 4.8 后退 `$[<n]`

从**当前游标**向段首方向移动 `n` 字节。

| 项目 | 说明 |
|------|------|
| 语法 | `$[<n]`，`n` 为非负整数 |
| 游标变化 | `游标 −= n`（相对当前游标，不是相对段尾） |
| 产生参数 | 否 |
| 失败条件 | `n > 游标`；游标在段首（0）时，任何 `n > 0` 都失败 |

> **易错点（务必注意）**：`$[<n]` **不是**「从段尾回退 `n` 字节」。
> 它只相对当前游标后退。如果游标还停在段首，`$[<1]` 就会失败。
> - 想「从段尾回退」，先把游标推到段尾，再后退：`${}$[<n]` 或 `$[END]$[<n]`；
> - 或者直接使用绝对形式 `$[END-n]`（通常更清晰）。

示例 1（先把游标推到段尾，再回退）：

```
模式：${}$[<4]${4}
段：  "document.pdf"（12 字节）
游标：0 → 12 → 8 → 12
解析：${} 捕获整段并把游标推到段尾；$[<4] 后退到 8；${4} 捕获 ".pdf"
结果：参数 ["document.pdf", ".pdf"]
```

示例 2（回退 1 字节取最后一个字节）：

```
模式：${}$[<1]${}
段：  "abc"（3 字节）
游标：0 → 3 → 2 → 3
结果：参数 ["abc", "c"]
```

示例 3（等价写法对比，推荐后者）：

```
模式 A（相对回退）：$[END]$[<4]${}     段 "document.pdf" → 参数 [".pdf"]
模式 B（绝对定位）：$[END-4]${}        段 "document.pdf" → 参数 [".pdf"]
```

示例 4（游标在段首，后退失败）：

```
模式：$[<1]${}
段：  "abc"（3 字节）
游标：0
结果：1 > 0 → 失败

模式：${2}$[<3]
段：  "ab"（2 字节）
游标：0 → 2
结果：3 > 2 → 失败
```

### 4.9 向段尾查找 `$[>'文本']`

从当前游标向段尾方向查找「文本」，命中后把游标移动到该文本的**首字节**。

| 项目 | 说明 |
|------|------|
| 语法 | `$[>'文本']` |
| 游标变化 | 游标 = 从当前游标起**第一个**命中的起始位置（命中在游标处时游标不变） |
| 产生参数 | 否 |
| 失败条件 | 从当前游标到段尾之间找不到该文本 |

示例 1（跳到分隔符之后取值）：

```
模式：$[>'=']$[>1]${}
段：  "q=router"（8 字节）
游标：0 → 1 → 2 → 8
解析：$[>'='] 命中下标 1 的 '='；$[>1] 跳过它；${} 捕获 "router"
结果：参数 ["router"]
```

示例 2（命中位置就是当前游标）：

```
模式：$[>'a']${}
段：  "abc"（3 字节）
游标：0 → 0 → 3
结果：参数 ["abc"]（查找从当前游标本身开始尝试）
```

示例 3（多字节目标 + 组合使用）：

```
模式：$[>'：']$[>3]${}
段：  "用户：alice"（14 字节）
游标：0 → 6 → 9 → 14
解析：全角冒号占 3 字节，命中首字节 6；$[>3] 跳过；${} 捕获 "alice"
结果：参数 ["alice"]
```

示例 4（找不到 → 失败）：

```
模式：$[>'#']${}
段：  "abc"（3 字节）
结果：段内不存在 '#' → 失败
```

### 4.10 向段首查找 `$[<'文本']`

向段首方向查找「文本」，命中后把游标移动到该文本的**首字节**。

| 项目 | 说明 |
|------|------|
| 语法 | `$[<'文本']` |
| 游标变化 | 游标 = 向前最近的命中起始位置 |
| 产生参数 | 否 |
| 失败条件 | 找不到该文本 |

查找起点的规则：

- 起点是**当前游标的前一字节**（不包含当前游标处本身）；
- 当游标位于段首（0）时，从**段尾前一字节**开始向前扫描。

示例 1（游标在段首 → 从段尾向前扫描）：

```
模式：$[<'=']${}
段：  "name=alice"（10 字节）
游标：0 → 4 → 10
解析：游标为 0，从下标 9 向前扫，命中下标 4 的 '='；${} 捕获 "=alice"
结果：参数 ["=alice"]
```

示例 2（取最后一个分隔符之后的内容）：

```
模式：$[<'=']$[>1]${}
段：  "name=alice"（10 字节）
游标：0 → 4 → 5 → 10
结果：参数 ["alice"]
```

示例 3（校验扩展名，不产生参数）：

```
模式：$[<'.']$'.pdf'
段：  "doc.pdf"（7 字节）
游标：0 → 3 → 7
解析：反向命中最靠后的 '.'（下标 3），再比对 ".pdf"
结果：无参数；游标 7 = 段长 → 成功
```

示例 4（游标不在段首：从游标前一位开始）：

```
模式：${12}$[<'.']${}
段：  "document.pdf"（12 字节）
游标：0 → 12 → 8 → 12
解析：${12} 捕获整段，游标 12；$[<'.'] 从下标 11 向前扫，命中下标 8 的 '.'
结果：参数 ["document.pdf", ".pdf"]
```

示例 5（不会命中游标处本身的文本）：

```
模式：${2}$[<'.']${}
段：  "a..b"（4 字节：'a'、'.'、'.'、'b'）
游标：0 → 2 → 1 → 4
解析：${2} 捕获 "a."（下标 0..1），游标停在下标 2 的 '.' 上；
     $[<'.'] 从下标 1 开始向前找，命中的是下标 1 的 '.'，而不是游标处的下标 2
结果：参数 ["a.", "..b"]
```

示例 6（找不到 → 失败）：

```
模式：$[<'#']${}
段：  "abc"（3 字节）
结果：段内不存在 '#' → 失败
```

## 5. 执行模型

### 5.1 段内游标与执行顺序

1. 每个段拥有一个独立的**段内游标**，单位是字节，初始值为 `0`（段首）。
2. 设段长为 `N`（字节），游标始终满足 `0 ≤ 游标 ≤ N`；`游标 = N` 表示停在段尾。
3. 模式中的操作按**书写顺序**依次执行；每个操作执行完成后更新游标。
4. 每个操作执行前都要做边界检查，任何操作失败 → 该段匹配失败 → 该路由不命中。
5. 段与段之间互不影响，也没有跨段操作；每段独立匹配，要求 URL 的段数与模式段数一致。

本语法**没有**分支、可选、重复等结构，也**没有**自动回溯：模式是确定的线性操作序列。
文档中说的「回溯捕获」是指用 `$[0]`、`$[END]` 等操作**显式地**把游标移回去重新解析
（见 9.6），而不是引擎在失败后自动尝试其它切分。

### 5.2 边界检查表

设执行某操作前的游标为 `pos`、段长为 `N`（单位均为字节），`len(文本)` 为文本字节数：

| 操作符 | 边界条件 | 违反时 |
|--------|----------|--------|
| `$'文本'` | `pos + len(文本) ≤ N` 且各字节完全相等 | 该段失败 |
| `${n}` | `n ≥ 1` 且 `pos + n ≤ N` | `n = 0` 编译报错；否则该段失败 |
| `${'文本'}` | 从 `pos` 起存在命中位置 `k`，且 `k + len(文本) ≤ N` | 该段失败 |
| `${}` | 无限制（`pos` 可以已经是 `N`） | 不会失败 |
| `$[n]` | `0 ≤ n ≤ N` | 该段失败 |
| `$[END]` / `$[END-n]` | `0 ≤ n ≤ N` | 该段失败 |
| `$[>n]` | `pos + n ≤ N` | 该段失败 |
| `$[<n]` | `n ≤ pos` | 该段失败 |
| `$[>'文本']` | 存在 `k ∈ [pos, N − len(文本)]` 命中 | 该段失败 |
| `$[<'文本']` | 存在 `k` 命中，其中 `k ∈ [0, pos−1]`（`pos = 0` 时取 `k ∈ [0, N−1]`） | 该段失败 |

### 5.3 段尾对齐

匹配成功需同时满足「操作耗尽」与「游标恰好位于段尾」。这条规则确保模式完整消耗整个段，
避免部分匹配造成歧义。

```
模式：${2}
段：  "ab"（2 字节）   → 游标 2 = 2 → 匹配成功，参数 ["ab"]
段：  "abc"（3 字节）  → 游标 2 ≠ 3 → 匹配失败

模式：${2}$'c'
段：  "abc"（3 字节）  → 游标 2 → 3 = 3 → 匹配成功，参数 ["ab"]
```

对应的路由级例子（模式 `/$'user'/${2}`）：

```
URL /user/ab   → 第 2 段 "ab"：游标 2 = 2 → 命中
URL /user/abc  → 第 2 段 "abc"：游标 2 ≠ 3 → 不命中
URL /user/abc  → 若模式为 /$'user'/${2}$'c'：游标 2 → 3 = 3 → 命中
```

几种常见的「天然对齐」结尾：

- 以 `${}` 结尾：游标一定被推到段尾；
- 以 `$[END]` / `$[END-n]${n}` 结尾：游标落在段尾；
- 以 `$'文本'`、`${n}` 结尾：只有恰好消耗到段尾才成功。

### 5.4 匹配阶段与提取阶段

每个段模式在注册时被编译成两条序列：**匹配序列**与**提取序列**。

- **匹配阶段**（`router_match`）：只执行比对与移动。捕获操作在这里只负责「前进」：
  `${n}` 前进 `n` 字节，`${'文本'}` 向段尾查找定界文本，`${}` 前进到段尾；不写入任何参数。
  因此匹配很快，且不需要参数缓冲区。
- **提取阶段**（`router_extract`）：路由命中后，对同一 URL 再执行提取序列，
  写入参数。此时已经验证过的字面量直接跳过，只做移动与捕获。
- 参数只有在真正调用 `router_extract` 时才产生，这就是「匹配与提取分离」。

同一层中，若两条不同路由编译出的匹配序列完全相同，它们会共享同一个节点
（例如 `${2}` 与 `$[>2]` 都编译为「前进 2 字节」，因此 `/$'x'/${2}/$'a'` 与
`/$'x'/$[>2]/$'b'` 的中间节点是同一个）。匹配只看匹配序列，命中后再由该叶子自己的
提取序列取参数。

## 6. 参数规则

1. **按操作顺序存储**：段内参数按捕获操作的书写顺序依次写入参数数组。
   一个捕获操作（`${n}`、`${'文本'}`、`${}`）产生一个参数。
2. **按段顺序连接**：多段模式下，第 0 段的参数在前，其后依次是第 1 段、第 2 段的参数。
   例如 `/$'user'/${}/$'posts'/${}` 匹配 `/user/bob/posts/42` 得到 `["bob", "42"]`。
3. **零拷贝**：`route_param_t.ptr` 直接指向原始 URL 字符串内部的字节，
   `len` 是该参数的字节长度；不会复制内容。
4. **空参数**：参数长度可以为 0，用 `len == 0` 表示（`ptr` 仍指向 URL 内的位置）。
   - `${}` 在游标已在段尾时 → 空参数；
   - `${'文本'}` 在定界文本正好位于游标处时 → 空参数。
   可用 `router_param_is_empty()` 判断。
5. **参数个数**：等于模式中捕获操作的总数。`$'文本'`、`$[n]`、`$[END]`、`$[END-n]`、
   `$[>n]`、`$[<n]`、`$[>'文本']`、`$[<'文本']` 都不产生参数。
   提取时提供的缓冲区容量不足，`router_extract()` 会返回 `-1`。
6. **提取阶段的参数起始位置必须字节对齐**：参数的比特偏移必须是 8 的整数倍。
   URLRouter 的步长固定为 8 且游标以字节计，因此该条件**天然满足**，实际使用中不会触发；
   这一约束在步长小于 8 比特时才会成为限制。
7. **生命周期**：参数指向原始 URL，因此在参数使用期间 URL 必须保持有效；
   不要释放或修改 URL 缓冲区。
8. **转换为字符串**：`router_param_to_string(param, buf, buf_size)` 把参数复制为
   NUL 结尾字符串（缓冲区由调用方提供），返回参数的实际长度。
9. **提取前提**：`router_extract()` 会用节点的分隔符重新切分 URL，并要求 URL 的段数与
   命中路由的段数一致，否则返回 `-1`。此外，只有命中叶子路由（带回调）时才有参数可提取。

示例：

```c
router_register(r, HTTP_GET, "/$'user'/${}/$'posts'/${}", handler, NULL);

route_node_t *node = router_match(r, HTTP_GET, "/user/bob/posts/42");
route_param_t params[8];
size_t count = 0;
router_extract(node, "/user/bob/posts/42", params, 8, &count);
/* count == 2
   params[0] = { ptr -> "/user/bob/posts/42" 中的 "bob", len = 3 }
   params[1] = { ptr -> "/user/bob/posts/42" 中的 "42",  len = 2 }
   两者都是零拷贝，指向原始 URL */
```

## 7. 分隔符

分隔符由 `router_create(char sep)` 指定：

```c
router_t *url_router  = router_create('/');   /* URL 路径 */
router_t *conf_router = router_create('.');   /* 点路径，如 .a.user.alice */
```

| 规则 | 说明 |
|------|------|
| `sep` 不能是 `'\0'` | `router_create('\0')` 返回 `NULL` |
| 模式必须以分隔符开头 | `"user/profile"` 非法，`"/user/profile"` 合法；点路径 `"a.user"` 非法，`".a.user"` 合法 |
| 分隔符不属于段模式内容 | 切分时它已被去掉，段模式只描述单个段；段内不含分隔符，因此不需要也不能用 `$'/'` 去匹配它 |
| 连续分隔符被拒绝 | `"/a//b"`、`".a..b"` 产生空段，注册与匹配都会失败 |
| 只有分隔符本身 | `"/"` 或 `"."` 切分出 0 个段，注册失败；匹配同样失败（本库不支持根路径路由） |
| 尾随分隔符被忽略 | `"/user/alice/"` 与 `"/user/alice"` 段数相同、结果一致 |
| 查询串不分段 | `?`、`&`、`=` 都留在段内；`/search?q=router` 只有 1 段 `"search?q=router"`，查询参数需在段模式内解析（见 9.3） |
| 多字节分隔符不支持 | `sep` 是单个字节；UTF-8 多字节字符不能作为分隔符 |
| 每个路由器各自独立 | 分隔符记录在路由节点上，提取时按同一分隔符重新切分 URL |
| HTTP 方法隔离 | 每种 HTTP 方法一棵独立路由树；同一模式可在不同方法下分别注册，匹配时方法必须一致 |
| 重复注册返回 -1 | 同一方法下重复注册完全相同的模式会因冲突而失败；也请避免注册互为段前缀的模式（如 `/$'user'/${}` 与 `/$'user'/${}/$'posts'/${}` 同时存在），以免产生歧义 |

点路径示例（分隔符 `.`）：

```
模式：.a.user.${}
URL： .a.user.alice
段 0: "a"       → 比对 "a"
段 1: "user"    → 比对 "user"
段 2: "alice"   → ${} 捕获 "alice"
捕获结果：["alice"]
```

## 8. 语法限制汇总

1. **段模式不能为空**：空字符串、空段（连续分隔符）、只有分隔符的路径都不能注册；
   编译器对空模式报「空段」错误。
2. **每个操作必须以 `$` 起始**：`$` 之外出现任何游离字节（分隔符、空格、字母等）
   都是语法错误；`$` 后面只能跟 `'`、`{`、`[` 三者之一。
3. **偏移/位置必须是非负十进制整数**：不接受 `+`、负号、小数、十六进制，
   即 `$[+1]`、`$[-1]`、`$[0x2]`、`$[1.5]` 均非法。`$[0]`、`$[>0]`、`$[<0]` 合法（不移动）。
4. **`${n}` 中 `n` 必须是正整数且 `n ≠ 0`**：`${0}`、`${00}` 都是语法错误；
   想捕获到段尾请用 `${}`。
5. **`END` 必须全大写且大小写敏感**：`$[end]` 非法；`END` 后只能跟 `-` 加非负整数，
   即 `$[END]`、`$[END-0]`、`$[END-4]` 合法，`$[END+4]`、`$[END-]`、`$[END 4]` 非法。
6. **文本参数必须用单引号包裹并闭合**：`${abc}`、`${'abc}`、`$'abc`、`$[]`、`$[>]`
   都是语法错误；`$[>'abc]` 也因缺少引号而非法。
7. **转义只允许白名单内的 7 种**：`\\`、`\'`、`\n`、`\t`、`\r`、`\0`、`\xNN`；
   `\x` 必须紧跟两位十六进制；其它反斜杠组合（如 `\.`、`\_`）非法。
8. **空文本要谨慎**：`$''` 合法（空比对、不消耗、不产生参数，等效于无操作）；
   `${''}`、`$[>'']`、`$[<'']` 语法上可写，但空目标在匹配阶段一律视为「未找到」，
   永远不会匹配成功，应避免。
9. **位置可以等于段长，但不能超过段长**：`$[n]`、`$[END-n]`、`$[>n]`、`${n}` 都以
   「不超过段尾」为边界；`n = 段长` 表示停在段尾。
10. **`${'文本'}` 的定界文本必须存在**：从当前游标起在段内找不到定界文本时，该段不匹配。
11. **`$[<'文本']` 的查找起点是游标前一位**：不会命中游标处本身的文本；游标在段首时
    从段尾前一位开始向前扫描。
12. **段尾对齐是硬性要求**：模式末尾必须把游标推到段尾（用 `${}`、`$[END]`，或让最后一个
    `$'文本'`/`${n}` 恰好结束），否则该段不匹配。
13. **单位是字节**：所有长度、位置、偏移都以字节计；UTF-8 多字节字符按实际字节数计算
    （`'：'` 是 3 字节，`'用户'` 是 6 字节）。
14. **编译失败时 `router_register()` 返回 `-1`**：语法错误对应
    `STRIDE_E_INVALID_PATTERN`，空模式对应 `STRIDE_E_EMPTY_SEGMENT`；
    路由冲突返回 `-1`。

## 9. 完整示例

以下示例均从 URL 路由视角给出：先切分，再逐段解析，最后给出捕获结果。
除特别说明外，分隔符为 `/`。

### 9.1 单段捕获 `/$'user'/${}`

```
URL： /user/alice
段 0: "user"    → $'user'  比对成功，游标 0 → 4
段 1: "alice"   → ${}      捕获整段，游标 0 → 5
捕获结果：["alice"]
```

### 9.2 多段参数 `/$'user'/${}/$'posts'/${}`

```
URL： /user/bob/posts/42
段 0: "user"   → $'user'  比对成功
段 1: "bob"    → ${}      捕获 "bob"
段 2: "posts"  → $'posts' 比对成功
段 3: "42"     → ${}      捕获 "42"
捕获结果：["bob", "42"]（按段顺序连接）
```

### 9.3 查询串解析 `/$'search'$'?'${'='}$'='${}`

查询串与路径同段，因此第 1 段是 `"search?q=router"`。

```
URL： /search?q=router
段 0: "search?q=router"（15 字节）
      下标：0..5 "search"，6 '?'，7 'q'，8 '='，9..14 "router"
  $'search'  游标 0 → 6     比对 "search"
  $'?'       游标 6 → 7     比对 "?"
  ${'='}     游标 7 → 8     命中下标 8 的 '='，捕获 "q"（下标 7）
  $'='       游标 8 → 9     比对 "="
  ${}        游标 9 → 15    捕获 "router"（下标 9..14）
捕获结果：["q", "router"]
```

### 9.4 版本号解析 `/$'api'/$'v'${'.'}$'.'${}`

```
URL： /api/v2.0
段 0: "api"   → $'api' 比对成功
段 1: "v2.0"（4 字节）
  $'v'        游标 0 → 1   比对 "v"
  ${'.'}      游标 1 → 2   命中下标 2 的 '.'，捕获 "2"
  $'.'        游标 2 → 3   比对 "."
  ${}         游标 3 → 4   捕获 "0"
捕获结果：["2", "0"]
```

### 9.5 定长字段解析 `/${4}$'-'${2}$'-'${2}`

```
URL： /2024-03-15
段 0: "2024-03-15"（10 字节）
  ${4}        游标 0 → 4   捕获 "2024"
  $'-'        游标 4 → 5   比对 "-"
  ${2}        游标 5 → 7   捕获 "03"
  $'-'        游标 7 → 8   比对 "-"
  ${2}        游标 8 → 10  捕获 "15"
捕获结果：["2024", "03", "15"]

等价写法（带前缀段）：/$'logs'/${4}$'-'${2}$'-'${2}
URL /logs/2024-03-15 → 捕获结果同样是 ["2024", "03", "15"]
```

长度不足时该段不匹配：`/2024-3-5` 的第 0 段只有 8 字节，
`${4}$'-'${2}$'-'${2}` 无法恰好消耗到段尾，路由不命中。

### 9.6 显式回溯捕获 `/${}$[0]${'.'}$'.'${}`

先用 `${}` 捕获整段，再用 `$[0]` 把游标移回段首，重新解析一遍。这不是引擎自动回溯，
而是模式作者显式重新定位游标。

```
URL： /document.pdf
段 0: "document.pdf"（12 字节）
  ${}         游标 0 → 12   捕获 "document.pdf"（参数 0）
  $[0]        游标 12 → 0   绝对定位回段首
  ${'.'}      游标 0 → 8    向段尾查找，命中最靠前的 '.'（下标 8，即 "document"
                            之后的那一个），捕获 "document"（参数 1）
  $'.'        游标 8 → 9    比对 "."
  ${}         游标 9 → 12   捕获 "pdf"（参数 2）
捕获结果：["document.pdf", "document", "pdf"]
```

### 9.7 反向查找 `$[<'=']`

**示例 A：取最后一个 `=` 及其后内容**

```
URL： /name=alice
段 0: "name=alice"（10 字节，下标 4 是 '='）
  $[<'=']     游标 0（段首）→ 从下标 9 向前扫描 → 命中最靠后的 '='（下标 4）
              游标 0 → 4
  ${}         游标 4 → 10   捕获 "=alice"
捕获结果：["=alice"]
```

**示例 B：只取最后一个 `=` 之后的值**

```
URL： /name=alice
段 0:
  $[<'=']     游标 0 → 4    定位到最后一个 '='
  $[>1]       游标 4 → 5    跳过 '='
  ${}         游标 5 → 10   捕获 "alice"
捕获结果：["alice"]
```

**示例 C：等价做法**

```
想「从段尾回退若干字节」时，用绝对定位更直观：
  $[END-5]${}   段 "name=alice"（10 字节）→ 游标 10−5 = 5 → 捕获 "alice"
```

### 9.8 综合：查找 + 定长 + 反向查找 `/$'log'/$[>'_']$[>1]${8}$[<'_']${}`

```
URL： /log/2024-03-15_ERROR_message
段 0: "log"        → $'log' 比对成功
段 1: "2024-03-15_ERROR_message"（24 字节）
      下标：0..9 "2024-03-15"，10 '_'，11..15 "ERROR"，16 '_'，17..23 "message"
  $[>'_']     游标 0 → 10    向段尾查找第一个 '_'
  $[>1]       游标 10 → 11   跳过 '_'
  ${8}        游标 11 → 19   捕获下标 11..18 = "ERROR_me"（参数 0）
  $[<'_']     游标 19 → 16   从下标 18 向前扫，命中下标 16 的 '_'
  ${}         游标 16 → 24   捕获下标 16..23 = "_message"（参数 1）
捕获结果：["ERROR_me", "_message"]
```

### 9.9 点路径（分隔符 `.`）

```c
router_t *r = router_create('.');
router_register(r, HTTP_GET, ".a.user.${}", handler, NULL);
```

```
URL： .a.user.alice
段 0: "a"      → $'a'    比对成功
段 1: "user"   → $'user' 比对成功
段 2: "alice"  → ${}     捕获 "alice"
捕获结果：["alice"]

非法写法：a.user（不以分隔符开头）、.a..b（空段）
```

## 附录 A：常见误写与纠正

| 误写 | 问题 | 正确写法 |
|------|------|----------|
| `$[<4]` 当作「从段尾回退 4 字节」 | `$[<n]` 是相对**当前游标**后退；游标在段首时 `$[<4]` 会失败 | `$[END-4]`，或 `${}$[<4]`（先把游标推到段尾再后退） |
| `$[<'\.']` | `\.` 不是合法转义，语法错误 | `$[<'.']`（点号直接写） |
| `$[>'\_']` | `\_` 不是合法转义，语法错误 | `$[>'_']`（下划线直接写） |
| `$'\/'` 或 `$'/'` 去匹配分隔符 | 分隔符在切段时已被去掉，段内不含它 | 段模式只描述段内容；分隔符由 URL 结构保证 |
| `${0}` | `n` 必须为正整数 | 用 `${}`（捕获到段尾），或删掉该操作 |
| `${00}` | 解析为 0，同样非法 | 明确写正整数 |
| `$[END+4]` | `END` 后只能跟 `-n` | 要后退用 `$[END-4]`；要前进用 `$[>4]` |
| 把 `END` 当成 `$[位置]` 的「第四种形式」 | `END` 的形式就是 `$[END]` / `$[END-n]` | 直接写 `$[END]` 或 `$[END-n]` |
| `$[end]` | `END` 大小写敏感且必须全大写 | `$[END]` |
| `\x9` | `\x` 必须紧跟两位十六进制 | `\x09` |
| `${'x'}` 期望「找不到就捕获整段」 | 匹配阶段找不到定界文本会导致该段不匹配 | 如需可选的定界，改用 `${}`、`$[>'x']` 等组合 |
| 结尾只写 `${2}` 却期望匹配更长的段 | 段尾对齐要求游标恰好到段尾 | 补 `$[END]`，或把剩余内容也捕获/比对 |
| 在模式里写 `*`、`?`、`[...]` 正则语法 | 本语法没有正则、通配符、可选与重复 | 只用本文档列出的 10 个操作码 / 9 类书写形式 |

## 附录 B：语法产生式（近似）

```
段模式   = 操作 { 操作 }
操作     = 精确比对 | 定长捕获 | 定界捕获 | 段尾捕获
         | 绝对定位 | 段尾定位 | 前进 | 后退 | 正向查找 | 反向查找

精确比对 = "$" "'" 文本 "'"
定长捕获 = "$" "{" 正整数 "}"
定界捕获 = "$" "{" "'" 文本 "'" "}"
段尾捕获 = "$" "{" "}"
绝对定位 = "$" "[" 非负整数 "]"
段尾定位 = "$" "[" "END" [ "-" 非负整数 ] "]"
前进     = "$" "[" ">" 非负整数 "]"
后退     = "$" "[" "<" 非负整数 "]"
正向查找 = "$" "[" ">" "'" 文本 "'" "]"
反向查找 = "$" "[" "<" "'" 文本 "'" "]"

正整数   = 非零数字 { 数字 }
非负整数 = 数字 { 数字 }
文本     = { 普通字节 | 转义 }
转义     = "\\" | "\'" | "\n" | "\t" | "\r" | "\0" | "\x" 十六进制 十六进制
```

说明：

- 一个段模式至少包含一个操作（空模式被拒绝）。
- 非终结符 `字面量`/`文本` 的长度单位是字节；空文本在语法上被接受，
  但其在匹配阶段的行为见第 8 节第 8 条。
- `END` 之外的字母都不构成合法操作；模式中不允许注释与空白填充。
